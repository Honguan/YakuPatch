## 邏輯摘要（Godot）

- **偵測**：遊戲資料夾內有 `GDPC` 開頭的 `.pck`。資料夾內每個 pck 都處理，因為遊戲可能在執行時載入其他 pck（ぶちこめ 的主程式會載入 `ozisanroom.pck`）。
- **提取範圍**：
  - `.tscn`／`.tres`：屬性 `text`、`bbcode_text`、`hint_tooltip`、`placeholder_text`、`dialog_text`、`window_title`、`tooltip_text`，含日文才取。
  - `.gdc`（Godot 3 位元組碼 12、13 版）：字串常數含日文、不像路徑，而且沒有在任何場景當節點名、動畫名等其他字串出現，也不是識別字。後者可能被程式拿來找節點或比對，翻了會壞。
- **寫回**：整個 pck 重寫。改過的檔案附加在檔尾，目錄裡的位移、大小、MD5 改指向新資料，其他資料不動；原檔留在備份。
- **字型**：譯文有中文字時，pck 內所有 `.ttf`／`.otf` 換成 Windows 中文字型（沿用 Unity 的選法：依繁簡與粗細選雅黑、正黑等）。
- **語言預檢**：pck 內有 `*.zh*.translation` 時回報內建中文。

## 邏輯摘要（Artemis）

- **偵測**：遊戲資料夾內有 `pf6`／`pf8` 開頭的 `<名稱>.pfs`。
- **封包順序**：遊戲先載入 `<名稱>.pfs`，再依編號載入 `.pfs.000`、`.001`……，後面的同名檔案覆蓋前面的。每個檔案只取最後生效的那份來翻。
- **提取範圍**：
  - `.ast`：Lua 表格，一行一個項目。只讀 `text = { ja = {...} }`：`name = {"話者"}` 取成 `name`，同一則訊息的每行字串取成 `dialogue` 並分在同一組；`select = { ja = {...} }` 的字串取成 `choice`。en／cn／tw 等其他語言不讀。
  - `.tbl`：`key = "文字",` 這種行，含假名才取（系統按鈕說明等），取成 `ui`。
  - 字串支援 `"..."`（含跳脫字元）與 `[[...]]`；寫回一律用 `"..."` 並跳脫。
- **寫回**：不改原封包。改過的檔案打包成新的 `<名稱>.pfs.NNN`，編號接在現有最大編號之後，格式（pf6／pf8）跟主封包相同。重建現有的中文補丁 `.pfs.001` 與 NUKITASHI 的 `.pfs.001` 都與原檔逐位元相同。
- **字型**：不換。實測遊戲用思源黑體，各地區版本都含簡繁字形；現成的中文補丁也只改劇本與表格。
- **語言預檢**：劇本裡有 `cn`／`tw`／`zh*` 區塊時回報內建中文。

## 邏輯摘要（Wolf RPG）

- **偵測**：有 `Game.exe`，且有 `Data/BasicData` 資料夾或 `.wolf` 封包。只支援散檔：`BasicData` 在 `.wolf` 封包內或 `.dat` 第一個位元組不是 0（加密）時拒絕，不解密。
- **格式**：依 WolfTrans 的格式說明自行解析（Wolf 2.2x 實測），每個檔案必須剛好解析到檔尾，否則報錯。字串是「長度＋CP932＋結尾 0」，檔案內沒有絕對位移，所以寫回只替換字串本身。
- **提取範圍**（地圖 `.mps` 與 `CommonEvent.dat` 的事件指令）：
  - 訊息（101）→ `dialogue`；選項（102）→ `choice`；顯示字串的圖片（150，類型 2）→ `ui`；字串變數設定（122）→ `other`，像路徑或檔名的不取。註解、除錯訊息不取。
  - `DataBase`／`CDataBase`：欄位類型為一般值（0）的字串欄位 → `ui`；選單、檔案等其他類型的欄位不取。`SysDatabase` 是系統變數名稱，不取。
  - 含日文才取。已被他人寫成 GBK 的字串（以 CP932 讀會變成半形片假名、半形標點或私用區字元）略過，並在語言預檢回報。
- **控制碼**：`\c[2]`、`\f[16]`、`\cdb[1:2:3]`、`\E`、`\.`、`<C>` 等遮罩成佔位符。訊息由我們自動換行（Wolf 不會自動換行）。
- **編碼（CP932 策略 D）**：CP932 有的字照寫；沒有的字（你、嗎、吧、她、說……）各分配一個遊戲完全沒用到的 CP932 罕用漢字（先 IBM 擴充漢字，再從 JIS 第二水準尾端往前），寫入那個字的編碼。再把 Windows 中文字型（依繁簡選正黑／雅黑）複製一份，把這些罕用漢字的字形指向對應的中文字，存成 `Data/YakuPatch.ttf`，並把 `Game.dat` 的字型名稱和這份字型的名稱都改成 `YakuPatch`（以 `_` 補足或截斷成原名稱的位元組長度：實測名稱長度改變或中間夾 NUL，Wolf 2.2x 啟動即崩潰）。遊戲仍以日文語系執行。
- **寫回**：改寫的地圖、公共事件、資料庫與 `Game.dat` 原檔留在備份；字型是新增檔案，還原時刪除。

## 新增 shortcut 與已知限制

- **字型全換**：pck 內所有字型都換成中文字型，包括只有英文的字型。沒有檢查字型原本缺哪些字。
- **`.gdc` 用猜的**：字串常數只要含日文、不像路徑、不和其他名稱重複就翻；被程式拿來比對的字串可能因此失效。和名稱重複的會保留原文，所以程式動態設定的部分按鈕提示可能仍是日文。
- **不支援**：加密 pck、嵌在 `.exe` 內的 pck、Godot 4 的二進位場景（`.scn`）與位元組碼、Dialogic 時間軸（`.dtl`）、動畫軌道裡的文字、Godot 4 匯入的字型（`.fontdata`）。
- **記憶體**：pck 整檔讀進記憶體，大小上限 512 MB。
- **合併重翻再分行**（pipeline，所有引擎）：多行訊息在逐批、去上下文、提高溫度都仍行數不符時，把各行接成一行重翻，再依原文各行長度切回同樣行數，切點會移到附近的標點。切點偶爾會落在詞中間（例如「好交／的／朋友」），只影響畫面換行位置。
- **翻譯紀錄檔**：每次翻譯寫 `~/.yakupatch/logs/<專案>-<執行編號>.jsonl`（不寫進遊戲），含設定、暫時性錯誤、每筆失敗句與模型原始回應、統計。
- **Artemis 讀音**：`{"txruby", text="讀音"}` 保留原樣，翻譯後讀音會標在中文字上方。
- **Artemis 範圍**：`.lua` 系統腳本（多是註解與除錯訊息）不翻；按鈕圖片上的文字不翻；跨行的 `[[...]]` 長字串不取。只支援 UTF-8 劇本。
- **Artemis 實測樣本**：庫內沒有純日文的 Artemis 遊戲，實測用的是移除中文補丁後的日文原版。
- **Wolf 範圍**：只支援散檔、未加密、CP932 的 Wolf 2.x；`.wolf` 封包（含加密）、Wolf 3 的 UTF-8 資料、`Game.dat` 的遊戲標題、事件名稱、`SysDatabase` 不處理。字串變數（122）用猜的：含日文且不像路徑就翻，被程式拿來比對的字串可能因此失效。
- **Wolf 字型**：整份 Windows 中文字型（約 20 MB）放進 `Data`，所有文字改用它顯示，原本的字型設定不再生效；替代字最多約 3,400 種（再扣掉遊戲用過的字）。若遊戲用 `\font[n]` 切到其他字型，那段的替代字會顯示成罕用漢字。
- **Wolf 實測樣本**：庫內唯一的散檔 Wolf 遊戲已被他人以 GBK 部分漢化；那些 GBK 字串需中文語系才能正常顯示，與本工具的日文語系寫法互斥，實機檢查只看本工具翻的句子。
